# Design

## Context

现有项目为 Vue 3 网页、Spring Boot API 和 PostgreSQL，已有邮箱会话、简历版本与上传、Mentor 主对话和旁聊、检索记忆、MiMo 文本模型调用以及 V10/V11 职业分析与逐项文字核验。旧流程对新用户强制选择方向，报告按较细技术点逐题评估并即时反馈，和新规格不同。旧数据和用户会话需要可继续访问。

## Goals / Non-Goals

**Goals:**

- 以可恢复的状态和带来源的能力证据串联探索、诊断、学习、面试和岗位匹配。
- 在共享记忆、积分扣费及音视频会话中保留用户隔离和失败恢复能力。
- 允许现有用户与数据增量迁移，避免将历史自评冒充已验证能力。

**Non-Goals:**

- 首期企业端接收应用内简历和充值。
- 站外提醒、独立手机 App，以及按估算学习时间规划进度。

## Decisions

### 业务状态与能力证据

新增方向、能力模块和版本化基础路线，个人计划引用路线版本及独立的能力标识。证据记录来源、时间、适用能力、结果和用户归属，自评与验证分开，历史结果不可覆盖。方向切换建立候选意图与确认状态，明确确认后更新目标，关联可复用能力及需补充的诊断。路线更新通过稳定标识重新生成个人当前路线，已移除模块保留历史。

相比直接在路线条目上覆盖颜色，独立证据可支持跨方向复用、复习建议和岗位重算。旧的 V11 自评与单题结果保留来源和历史，是否足以构成新标准的验证由显式迁移规则确定，无法确定时标记待验证，不直接套用历史匹配分。

### Mentor 与记忆

沿用现有会话、旁聊和检索结构，增加面向用户状态与证据的长期记忆记录，区分学生陈述、模型推断、验证结论和来源，包含更正及删除状态。主对话和旁聊按需检索相关记录，取消面向用户的记忆浏览与编辑入口。遗忘意图必须进入确认流程，记录用户确认的对象和范围，完成后删除或失效对应记忆及明确选中的原始资料，同时清理检索索引及衍生摘要。涉及共享引用的历史数据由删除规则处理，避免重新生成被遗忘的内容。

### Java 与 Python 服务分工

Spring Boot 继续负责账号权限、简历、岗位、积分、学习进度、文字对话及长期记忆的权威读写。既有 MiMo 文字流式调用先保留，Spring AI 作为可选集成组件，接入前验证 MiMo 流式、结构化输出和工具调用兼容性；不用框架内置会话记忆替代跨旁聊的持久记忆与遗忘规则。

新增 Python 实时对话服务，负责电话和视频的实时对话编排、音频与视频处理及供应商适配。服务本身不作为账号、积分、简历或长期记忆的数据权威，也不直接写业务数据库。Java 对用户鉴权并授权会话，提供范围受限、短期有效的会话凭据；Python 通过内部受认证接口读取本次会话所需上下文，向 Java 提交必要要点、会话进度、用量和最终结果。双方使用会话 ID、账号绑定、修订号及幂等事件 ID，防止跨用户读取、重复写入与重复结算。传输方式及 Python 框架在供应商验证时选定。

浏览器与音视频供应商或 Python 服务的媒体链路取决于供应商能力，但不能向浏览器暴露供应商长期密钥。Java 保持积分预留和结算的唯一权威；Python 报告可核算用量和结束事件，断线、服务重启或重复回调通过会话状态恢复与幂等处理。长期记忆由 Java 根据必要要点和来源生成或更新，文字与音视频共享。实时会话期间的临时状态设定有效期并清理，结束后不得保留录音、录像或完整逐字稿。

保留现有 Java 文字对话可减少首次迁移范围；实时场景采用 Python 便于验证可用的音视频 SDK。是否日后合并文字编排以实际重复度、延迟和维护成本评估，不作为 MVP 前置条件。

### 诊断、实时会话与面试

定义探索、方向确认、诊断准备、诊断进行、暂停、完成等状态。AI 根据方向和简历挑选粗粒度关键模块，结合回答自适应追问，不逐个遍历所有技术点。完成条件为形成初步画像，缺失证据标记待验证。诊断完成后原子保存报告、证据、路线生成请求及匹配刷新任务。

浏览器电话仅使用麦克风，视频另需摄像头。Python 实时服务通过适配层接入具备所需语音与视觉能力的供应商，Java 保留 MiMo 文本调用；具体实时供应商和浏览器兼容性需先做技术及费用验证。会话实时维护必要要点和当前进度，意外中断可恢复。服务结束及异常清理时销毁临时媒体、逐字稿和中间缓存，长期只存报告、面经及必要要点；音视频使用过程中的临时状态须设置到期清理。视频仪态只生成辅助建议，不参与岗位分数。模拟面试选方向或具体岗位，结束统一反馈并保存面经，可从薄弱点打开相关旁聊。

### 岗位与匹配

岗位按来源和来源岗位标识去重，保存原文、版本、链接、状态、更新时间及最近核验时间；对可用的企业官网或授权合作接口采用按来源配置的定期增量同步，失败不误判为岗位关闭，管理员可维护及下架。BOSS 公开数据接口和各官网接入条件尚待核实，具体来源接入以前置验证和可用授权为准。

AI 对岗位版本抽取技术要求，对用户证据形成能力画像，保留来源及待验证状态；分数计算使用可版本化的评分规则，针对所有已收录岗位维护结果，按能力或岗位变更增量重算。待验证项不计已掌握，届别、地点、到岗时间、实习时长仅提示。用户诊断完成前不展示分数。全部岗位匹配可能存在异步刷新延迟，页面展示计算中或更新时间，避免旧值冒充最新结果。用户直接跳转来源投递，收藏及投递进度按账号保存。

### 简历版本和并发

将上传原件和结构化可编辑版本关联；解析失败时保留原件并提示用户补充，避免凭空生成经历。Mentor 变更须绑定能力证据、生成新版本并在主对话告知。采用版本号或乐观并发控制防止覆盖用户同时编辑的内容；冲突时重新基于最新版本生成变更。保持技能、学习成果和真实项目经历的证据类型。

### 积分与成本

建立一次性积分账户、按阶段的预留额度和不可变消费流水。请求带幂等标识，先原子预留额度，完成后按可核算实际用量结算，失败或中断释放未使用部分；通话以短周期结算并在不足前提醒，保留阶段进度。用户可查询余额、规则与消费记录，管理员调整留下审计记录。岗位自动批量匹配的计费归属与复用策略须纳入成本测算，不能因重试或后台重算重复扣费。

20 元是成本目标而非已验证的容量保证。先以真实供应商价格、语音时长、视频采样和模型请求量测算，再设定一次完整试用的具体轮数、时长、积分与阶段保留值。成本测算无法满足目标时需先调整方案，不以未验证的数字承诺试用容量。

## Risks / Trade-offs

- 跨服务调用和事件重试可能造成用户数据混用或重复结算 → 服务间认证、会话归属检查、修订号和幂等事件，覆盖断线重试测试。
- 实时语音视频服务、模型定价及单次试用成本未验证 → 先做供应商接入和端到端成本测试，再确定可执行额度。
- 企业岗位来源的访问与授权差异 → 按来源逐个核实、记录同步状态与原文链接，支持后台手工管理。
- AI 诊断和匹配可能判断错误 → 保留证据与待验证状态，支持用户提出纠正并触发核实。
- 高频刷新全部岗位带来计算和计费压力 → 缓存版本化解析结果、增量刷新并展示计算状态。
- 原始资料删除可能留下摘要或索引副本 → 对来源引用建立关联，确认后清理派生数据，验证不可再检索。
- 数据迁移后旧流程与新体验并存 → 增量迁移和可回退发布，已有数据保留且历史结论不自动提升为验证通过。

## Migration Plan

1. 备份并验证现有数据库迁移状态，以新增表和兼容字段承载能力证据、方向路线版本、会话、岗位与积分。
2. 为旧报告、简历、旁聊和 V11 结果建立来源映射，保留原始历史；对无法可靠映射的结果保持待验证。
3. 以可控开关引入新流程，验证现有账号、历史简历、主对话和旁聊可访问，再切换新用户入口。
4. 回退时关闭新入口并保留新增数据，恢复旧应用版本前确认数据库兼容；不得回滚删除用户新产生的数据。

## Open Questions

- 实时音视频、语音识别、语音合成与视觉分析的具体供应商，需要验证接口、浏览器体验和单次成本后选择。
- 邮箱验证列为可选项，接入邮件服务的可行性及上线时机待评估。

### 邮箱验证 MVP 决策
MVP 暂不引入邮箱验证码，继续使用邮箱和密码注册登录。上线前若启用验证，需要邮件服务商、发信域名及 SPF/DKIM 配置、密钥管理、验证码有效期和限流，以及投递失败和重发处理；实际服务成本待测算。
