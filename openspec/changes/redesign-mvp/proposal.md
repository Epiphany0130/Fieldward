# Proposal

## Why

循职需要以统一的产品目标重新整理既有需求，形成覆盖从方向探索到投递的可验收规格。现有文档中首次诊断与面试准备的流程存在冲突，需要按照已确认的产品决策重建基线。

## What Changes

- 建立以主动引导的 Mentor 为中心的完整求职与技术学习流程。
- 支持方向探索、简历分析、音视频诊断、学习路线和模拟面试。
- 建设可持续更新的岗位市场、基于能力证据的匹配与投递跟踪。
- 维护跨对话长期记忆、简历版本、一次性积分和管理后台。
- 以新的验收场景审视现有实现，并规划增量迁移与实现任务。

## Capabilities

### New Capabilities

- `career-diagnosis`: 简历、方向探索与首次水平诊断。
- `mentor-learning`: 主动引导、共享记忆、学习、面试和面经。
- `jobs-matching`: 岗位市场、匹配、收藏与投递进度。
- `resume-management`: 简历上传、版本管理与基于证据的自动更新。
- `accounts-operations`: 账号、积分、管理员与平台运营。

### Modified Capabilities

无。当前 OpenSpec 尚无已归档规格。

## Impact

影响网页及移动端适配、Java 业务后端、新增 Python 实时对话服务、账号和管理后台、简历、Mentor、岗位数据、积分计量以及数据库。现有实现需要对照新规格评估迁移与差异。
